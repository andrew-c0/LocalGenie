## Product
- LocalGenie = Tauri 2 desktop UI over Qualcomm's GenieX CLI (`geniex`), which runs local LLMs on CPU/GPU/NPU. Primary target: Windows ARM64.
- Model path for Hugging Face GGUF: the app downloads the file itself (`download_file`, resumable via `<file>.part` + HTTP Range), then imports it with `geniex pull <repo>:<precision> --model-hub localfs --local-path <dir>` (`import_gguf`). Hub pulls are no longer used by the app.
- Qualcomm AI Hub code is legacy-in-progress, not to be expanded: `list_aihub_models`, `AihubModel`, `ModelInfo.source = "aihub"`, the "qualcomm" browse area (HF `author=qualcomm` intersected with `geniex model list`, `compatibleNames`). The compat badge input `assetCompat` is never populated (no caller of `setAssetCompat`).
- Unit tests: vitest (`npm test`), files `*.test.ts` in `utils/` and `services/database.test.ts`. Rust: inline `#[cfg(test)]` modules (`cargo test`), including the migrations and `model_settings.rs`. No UI tests. Backlog: `tasks.md` (user-owned).

## Stack
React 19 + TS 5.8 + Vite 6, Fluent UI v9 (`@fluentui/react-components`), zustand 5, react-router-dom 7 (MemoryRouter), react-markdown + rehype-highlight. Biome for lint/format. Rust: tauri 2 (`tray-icon` feature; `tray.rs`), tauri-plugin-shell (capability `shell:allow-open` only; the GenieX CLI is run from Rust, not via the shell plugin), tauri-plugin-dialog (`dialog:allow-open`; uncommitted, used by `pick_text_file`), sea-orm 1 (SQLite), tokio, reqwest, sysinfo. Dev port 1420; GenieX server default port 18181.
Window: frameless (`decorations: false`, background `#292929`); the custom `shell/TitleBar/TitleBar.tsx` provides the chrome. Window-control permissions are in `src-tauri/capabilities/default.json`.
CSP (`src-tauri/tauri.conf.json`): `connect-src 'self' http://127.0.0.1:* ws://127.0.0.1:*` only. Webview `fetch` to huggingface.co is therefore not allowed as configured (see known-issues). Rust-side `reqwest` calls are not subject to CSP.

## Backend (`src-tauri/src/`)
- `lib.rs`: opens `geniex.db` in the app data dir, runs migrations, manages `AppState` and `DownloadRegistry`, registers commands, kills the server PID on window destroy. Modules also include `gguf.rs` and `tray.rs`.
- `commands/` (one domain per module): `models` (list, list_aihub, remove, clean, set_type), `hub` (search_models), `server` (start/stop/status, PID tracking), `chat` + `chat_helpers` (load_model, unload_all_models, chat_completion, cancel; `ModelLoadParams`, `apply_load_params`, `build_chat_body`), `cli` (check installed, config get/set/list, `resolve_geniex_executable`, `get_runtime_versions`), `cli_update` (check_for_cli_update, update_geniex), `download` (download_file, cancel_download), `import` (import_gguf, delete_directory), `database` (sessions, messages, chat errors, settings, model settings delegating to `model_settings.rs`, downloaded models), `files` (uncommitted: pick_text_file, read_text_file, file_exists; text files only, max 512 KB, UTF-8, no NUL bytes), `logs`, `system` (get_system_memory, uncommitted: get_platform_info), `constants`.
- `model_settings.rs` (uncommitted; `pub mod` in `lib.rs`): `setting_keys!` declares each setting key with its Rust type (`SettingKey`); `validate` checks a value's type; `load` skips unknown or invalid rows; `save` validates everything first, then in one transaction upserts the given keys and deletes the model's other keys. `SystemBlock` (`text`, `datetime`, `platform`, `file`) is the stored form of the system prompt blocks.
- Entities: `chat_session`, `message`, `chat_error`, `user_preference`, `downloaded_model` (name PK; precision, context_size, param_count, repo_url, model_card, timestamps), `model_setting_value` (uncommitted; PK model_id + key; `value` = JSON text, `updated_at`). The old `model_settings` table is kept with no entity and is unused (uncommitted).
- Migrations: `m20260730_000001_create_tables`, `m20261007_000001_downloaded_models`, `m20261020_000001_add_repo_columns`, `m20261022_000001_message_finish_and_errors` (`messages.finish_reason`, `chat_errors` table), `m20261022_000002_message_stats`, `m20261023_000001_model_setting_values` (uncommitted; creates `model_setting_values` and copies each old `model_settings` JSON object into it, one row per key, skipping null and the server keys; a saved single `systemPrompt` becomes a `legacy-text` block).

## Events (verified by grep of `emit`/listeners)
- `download-progress` `{ id, file, received, total, speed }`, `{ ..., complete: true }`, `{ id, file, cancelled: true }`. `id` = Hugging Face repo id (download id).
- `model-pull-start` `{ model }`, `model-pull-progress` `{ model, message }`, `model-pull-complete` `{ model }`: emitted by `import_gguf` only (GenieX local import). Listened to in `useDownloadManager.ts`.
- `chat-chunk` `{ streamId, content }`; `chat-done` `{ streamId, finishReason }` (also emitted on user cancel, with `finishReason` `cancelled`). Stats are computed in the frontend (`useChatStream.ts`).
- `server-stopped` (no payload; `useModelLoader`): emitted only when the `geniex serve` child exits without a user stop (uncommitted, `server.rs`). Stop and unload take the PID out of state before killing, so they do not emit it. `server-log` `ServerLogLine` (`ServerLogsCard`), `geniex-update-progress` `{ message }` (`CliUpdateCard`).

## Key flows
- GGUF download: `HubModelDetail` -> `downloadStore.enqueue(variant)` (status `queued`) -> `useDownloadManager` effect -> `runGGUFDownload` (`downloadPipeline.ts`): `download_file` (`.part`, Range resume, cancel via `cancel_download`) -> `import_gguf` (`model-pull-start` sets `importing`) -> `delete_directory(<folder>)` -> sidecars (best-effort). `model-pull-complete` sets `finished` and runs `refreshAfterImport` (downloaded-model row from Hub `context_length` or DB fallback, then CLI model list refresh). Cancel of a queued entry removes it; of an active entry calls `cancel_download`. Resume = `enqueue` again; the `.part` file is reused. Other failures set `error`.
- Model settings: stored per model in `model_setting_values` (one row per key; see Backend). Load parameters (`nctx`, `ngl`, `compute`, `powerMode`, `spec*`) are sent with the warmup and with every chat request, so the server does not reload. `grammarString`, `seed` and `think` (`enable_think`) are per-request generation settings. QAIRT (AI Hub) models ignore most of these (`utils/modelSettings.ts`, `loadSettingDisabledReason`). Server options (`origins`, `keepalive`) are app settings in `user_preferences`, not per model; changing them restarts the server.
- Context window: `resolveLoadParams` uses the saved `nctx`, else the model's native `context_size` (`db.loadNativeContext`), else omits `nctx` so the server default applies (4096 per `geniex-cli-reference.md`) (uncommitted). `ChatContextHeader` ring and `ModelSettings` display use the same order; `DEFAULT_CONTEXT_WINDOW` (4096) is used only when both are missing.
- Save of model settings (uncommitted): `ModelSettings` saves, then, if the model is loaded, `services/modelLoad.ts` `reloadModel`: stop server (unloads all) -> start server with saved server options -> `load_model` with the saved load params -> set active model and the active session's model. A failed reload shows an error toast; the model is left unloaded.
- Model load (header): `start_server` if not running or if its server settings (origins, keepalive) differ from the running server's (`serverOptions`; an external server is reused as is) -> `load_model` with the saved load params (1-token warmup request; checks the model is listed) -> active model. Compute change in the header only sets the default for the next message. Unload = stop the server (`unload_all_models`; the only unload mechanism; no per-model unload exists in GenieX).
- System prompt (uncommitted): stored as `systemBlocks` (`SystemPromptBlock`: `text`, `datetime`, `platform`, `file`). `ChatInput` composes it at each send with `composeSystemPrompt` (`utils/systemPrompt.ts`): datetime uses the current time and local zone; platform uses `getPlatformInfo` (cached) plus the chipset read once at startup (`AppBootstrap`, `configGet("chipset")`, into `modelStore`); files are read with `read_text_file` and wrapped in `--- file: name ---` delimiters. An unreadable file is left out and reported in an info toast. The composed text is sent as `systemPrompt` in the chat settings.
- Chat: `ChatInput` sends with a `streamId` and the model's settings (`chatSettingsFor`); `chat-chunk`/`chat-done` are matched to `chatStore.activeStream` by id, so tokens go to the session that started the stream. Sessions are saved debounced (500 ms, changed sessions only) by `useSessionPersistence`, flushed on unmount. A failed send adds an error message and saves a `chat_errors` row. Streaming (uncommitted): `useChatStream` buffers `chat-chunk` text and writes it to the store once per animation frame (flushed on `chat-done`); `ChatArea` scrolls instantly while streaming.
- Toasts: only for operations the user waited on (download start/finish/cancel/fail, model load/switch/unload, chat failure, model removal, model settings saved). Not used for background list or conversation loads.
- CLI update: installer-based, see `cli-update.md`.
