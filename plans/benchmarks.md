# Benchmarks area (final plan)

Status: approved for implementation, not started. Replaces the Prompt Benchmark playground and the Performance Dashboard. Design note, not maintained by knowledge-sync.

## Scope
- Prompt library, with optional files per prompt.
- Test-run (suite) editor: ordered steps, each a prompt plus optional extra files.
- Runner in Rust: streams through the local server, measures timing, samples resources, checks keywords.
- Runs table with row selection, and Compare charts (Fluent) with mean and min/max over repetitions.
- CSV export of the runs table; PNG export of every Compare chart.

## Decisions
- Suite mode: **conversation** (steps share history) or **independent** (fresh request per step). Both supported.
- Each run: one discarded warmup pass of the whole suite, then N timed repetitions. Compare shows the mean with min/max.
- Keywords: per prompt, rule `all` or `any`, whole word, case-insensitive. Result per step: `passed` (null when the prompt has no keywords), matched and expected counts.
- Resources: summaries per step only (peak and average model RAM, system memory used, CPU, GPU, NPU). No per-second series.
- Not captured: bandwidth, thermals, power (no backend source).
- Compute target is a load parameter. If the run's compute differs from the loaded model, the UI asks before reloading. No automatic reload.
- Concurrency: a run waits for the server. Chat is disabled while a run is active or a reply is streaming.
- Conversation mode: a failed step (error, timeout, cancel) stops the run; remaining steps are recorded as skipped.
- Deletion: hard delete with confirmation for prompts, suites and runs.
- Files: copied into `<app data>/benchmark-files/<id>/<name>` when added. Owned by the prompt. Removed when no prompt or step references them any more. Run history keeps its own snapshot (prompt text, file name, size, hash). A startup sweep removes orphaned files.

## Data model (structured tables, no JSON columns)
- `benchmark_prompts`: id, name, description, match_rule (`all` | `any`), created_at, updated_at.
- `benchmark_prompt_keywords`: id, prompt_id, keyword, position.
- `benchmark_files`: id, name, kind (`text` | `image` | `audio`), size, chars, stored_path, sha256, created_at.
- `benchmark_prompt_files`: prompt_id, file_id, position.
- `benchmark_suites`: id, name, description, mode (`conversation` | `independent`), warmup_runs, repetitions, created_at, updated_at.
- `benchmark_suite_steps`: id, suite_id, position, prompt_id (foreign key to the prompt; deleting a prompt is blocked while a suite uses it, see Open below).
- `benchmark_step_files`: step_id, file_id, position.
- Ids are strings generated by the frontend, like the existing tables. Junction rows use composite keys with `position`.
- Repetitions are one run: `benchmark_run_steps.repetition_index` and `is_warmup` identify each pass. There is no batch table.
- `benchmark_runs`: id, suite_id (nullable, cleared on suite delete), suite_name snapshot, model_name, model_key, compute, precision, nctx, ngl, power_mode, temperature, top_p, seed, max_tokens, mode, warmup_runs, repetitions, geniex_version, chipset, total_memory_bytes, status (`running` | `completed` | `failed` | `cancelled`), error, started_at, finished_at.
- `benchmark_run_steps`: id, run_id, position, repetition_index, is_warmup, prompt_name, prompt_text, output_text, ttft_ms, total_ms, tokens_per_sec, prompt_tokens, completion_tokens, peak_model_memory_bytes, avg_model_memory_bytes, peak_memory_used_bytes, avg_cpu, avg_gpu, avg_npu, passed (nullable), matched_keywords, expected_keywords, status (`completed` | `failed` | `skipped`), error.
- `benchmark_run_step_files`: run_step_id, file_name, file_size, file_sha256 (snapshot, no foreign key to the file).

## Build order
1. Migrations, entities, `services/benchmark.ts` contract, types. (rust-expert, then repo-default for the IPC contract.)
2. Prompt library and file copy/cleanup, with a startup orphan sweep.
3. Suite editor (steps, files, mode, repetitions, warmup).
4. Runner: warmup, timed repetitions, keyword check, resource sampling, cancel, timeouts, `benchmark-progress` and `benchmark-finished` events, server-busy lock.
5. Runs table: sorting, filters, checkbox selection, CSV export.
6. Compare charts: mean with min/max, grouping by model, compute and time. PNG export.
   - Spike first: confirm Fluent chart colors survive SVG-to-PNG. If not, add `html-to-image` and say so before adding it.
7. Remove the old playground, dashboard, `benchmarkStore` and the raw `fetch` in the Playground. Update `memories/repo` and the manual checklist.

## Tests
- vitest: keyword matching, mean and min/max aggregation, CSV building.
- cargo test: metric math, keyword matching in Rust (if the check runs in Rust), migrations, orphan sweep.
- Live run against a loaded model for a conversation suite and an independent suite.

## Open
- Deleting a prompt that a suite still uses: block it with a message listing the suites, or remove those steps too? Not decided. Default: block it.
