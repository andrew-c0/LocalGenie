# Repo scan: bugs, IPC communication, and code health

Scope: whole repo except the benchmark pages (`src/pages/benchmark/*`, `src/components/benchmark/*`, `src/stores/benchmarkStore.ts`), which are out of scope for now.

Baseline before the scan: `npx tsc --noEmit` passes, `node_modules/.bin/biome check src` is clean (60 files), `cargo clippy --all-targets` reports no warnings at default lints. There are no tests (`vitest` is installed, no test files).

Not verified at runtime. Each finding below was traced by reading the code. Items marked **verify** depend on runtime behaviour and should be confirmed in `npm run dev` before fixing.

Read in full: `src-tauri/src/commands/*`, `lib.rs`, `src/services/*`, `src/stores/chatStore.ts`, `modelStore.ts`, `downloadStore.ts`, `src/hooks/index.ts`, `src/components/AppBootstrap.tsx`, `ChatInput.tsx`, `ModelSelectorPopover.tsx` (lines 100–210), `LocalModelsBrowserPage.tsx` (lines 60–230), `Navigation.tsx`, `tauri.conf.json`, `capabilities/default.json`. Not read in detail: `ChatArea`, `MessageBubble`, `HubModelBrowser`, `Overview`, `types/index.ts`.

## 1. Bugs in features that look like they work

Ordered by user impact.

1. **Download cancel never reaches the running download.** `DownloadDrawer.tsx` calls `cancelDownload(id)` where `id` is the repo id (`org/repo`). `download.rs:36` looks the flag up by file name, so nothing is found and cancel is a silent no-op.
2. **Resume from the drawer passes the repo id as the file name.** `DownloadDrawer.tsx:68` calls `downloadFile(url, id)`. That writes to `Downloads/org/repo`, which fails. The file name must be the basename of the GGUF.
3. **A partial download is treated as complete.** `download.rs:57` returns `Ok` if `target.is_file()`. A cancelled download leaves a partial file at that path, so the next attempt "succeeds" and imports a truncated GGUF. The resume branch in `run_download` (lines 78–102) is therefore unreachable for the same path. Fix: keep partial files under a `.part` name and rename on completion.
4. **Duplicate-download guard is always off.** `Navigation.tsx:27` creates `downloading` as an empty `useState` with no setter, and `HubModelDetail` receives it. `LocalModelsBrowserPage.tsx:78` and `:324` read `modelStore.downloads`, which nothing fills (`addDownload` has no callers; `AppBootstrap` writes to `downloadStore`). This is why `tasks.md` item 1 (double-clicking download) still happens. The download state should come from `downloadStore` (see 2.1).
5. **Server restart after a crash fails silently.** `server.rs:196–199` emits `server-stopped` when the child exits but does not clear `state.server_process`. `start_server` (lines 111–120) then sees `is_some()` and returns the not-running status without spawning. The user must press Stop first. Also, `stop_server` may later `taskkill` a stale PID that Windows has reused. Fix: clear the PID in the wait task, and check liveness before trusting it. **Verify** by killing `geniex.exe` from Task Manager and pressing Start.
6. **Import succeeds but reports failure when the README fetch fails.** In `download.rs:290–295` the `.send().await.map_err(...)?` returns early. The model is already imported, but `upsert_downloaded_model` is skipped and the UI shows an error. The card fetch should be best-effort (`.ok()`).
7. **Context size is ignored in the fallback.** `AppBootstrap.tsx:293–299`: the ternary binds the whole `??` chain, so the result is always `cfg.max_position_embeddings`, and `context_length` is dropped. Fix: `cfg.context_length ?? cfg.max_position_embeddings ?? cfg.max_sequence_length`.
8. **Install banner always fails.** `install_geniex` (`cli.rs:153–155`) always returns `Err`. `Layouts.tsx` (`CliMissingBanner`) shows "Install failed" every time. Replace the button with a link to the GenieX releases page, or hide it.
9. **Chat output can go to the wrong session.** `chat-chunk` and `chat-done` carry no session or stream id. `AppBootstrap` routes tokens to whichever session is active at that moment, so switching chats mid-stream moves the reply. See 2.2.
10. **Failed sends pollute the context.** `ChatInput.tsx:70–76` adds the error as an assistant message but does not save it to the DB. It is still sent as context on the next turn, and it disappears on reload.
11. **Session metadata is not saved reliably.** `AppBootstrap.tsx:92–103`: `persistSession` reads `activeSessionId` when the 500 ms timer fires, so a switch inside that window can skip the save for the previous chat. `useDebouncedCallback` also returns a new function each render, so the effect runs on every render instead of on session changes.
12. **Settings with no effect.** `ModelSettings.tsx:251–264` exposes "Context size" (`nctx`) and "Think" (`think`). `build_chat_body` (`chat_helpers.rs:70–110`) ignores both, and `start_server` is never given `nctx`. The controls do nothing.
13. **Stale-state UI in model selection.** `ModelSelectorPopover.tsx:103` keeps the compute target of the running server in a component `useRef` that defaults to `DEFAULT_COMPUTE` and is lost on unmount. It may wrongly restart a server that is already running on the requested target. Store it in `modelStore`, or take it from the backend status.
14. **CSP may block Hugging Face calls from the webview.** `tauri.conf.json` sets `connect-src 'self' http://127.0.0.1:* ws://127.0.0.1:*`. `hubApi.ts` (lines 116–214) calls `https://huggingface.co` with `fetch`, as does `AppBootstrap.tsx:288`. The codebase map already flags this. **Verify** in the Hub browser. If it is blocked, these calls should move to Rust commands, the way `search_models` already works.

## 2. Communication (frontend ↔ Rust)

### 2.1 One download lifecycle, three channels, and a module-level map

Model imports emit `model-pull-start/progress/complete`. HF file downloads emit `asset-download-progress`, keyed by file name. `AppBootstrap.tsx:17` keeps a module-level `fileToRepoMap` to translate file names back to repo ids.

Proposal:
- Rust emits one `download-*` event family (`start`, `progress`, `importing`, `complete`, `error`, `cancelled`), keyed by the download id the frontend supplied (the repo id).
- `cancel_download` and `download_file` take that id too, so cancel and resume match the drawer.
- Delete `fileToRepoMap`. Rename `model-pull-*` to match its real use, because hub pulls are legacy (see `codebase-map.md`).

### 2.2 Stream events need a stream id

`chat_completion` should return a `streamId`, and `chat-chunk`/`chat-done`/`chat-error` should carry it. The store then appends to the message that was started by that stream, not to the active session. This fixes 1.9.

Errors should also be emitted as an event. Today a failure before streaming rejects the `invoke` promise, while a failure mid-stream (`chat.rs:208`, the `?` on the chunk) returns `Err` without emitting `chat-done`. The UI then sees a rejected promise, but the streamed message stays half-written.

### 2.3 `useTauriEvent` re-subscribes on every render

`src/hooks/index.ts:36–45` has no dependency array. Each render calls `unlisten` and then `listen` again. Events emitted in the gap can be dropped, and the work is repeated on every render. Fix: keep the handler in a ref and subscribe once per event name (`useEffect(..., [event])`).

`AppSettings.tsx:74–82` calls `listen` directly. Use the hook instead.

### 2.4 Typed event and error contract

- Event payloads are built with `serde_json::json!` and typed ad hoc on the TS side. A `#[derive(Serialize)]` struct per event and one `src/types/events.ts` map would stop drift (for example, `asset-download-progress` has seven optional fields).
- Commands return `Result<T, String>`, so the UI matches on message text (for example `"Server returned"`). A small error enum serialized as `{ kind, message }` would let the UI show "CLI not found" differently from "timed out".

### 2.5 Smaller contract issues

- `unload_all_models` accepts `port`, but `geniex.ts` never sends it, so `stop_server` falls back to the default port.
- `load_model` derives the port by parsing the URL; pass the port explicitly.
- `download_file` is called with an unused `precision` argument (`download.ts:11`).
- `get_preference` guesses the type from the string (`database.ts:101–116`). A string preference of `"123"` comes back as a number. Store preferences as JSON and parse them as JSON.
- `DownloadedModelMeta` mixes `repo_url`/`model_card` with camelCase fields.

## 3. Rust backend

Best-practice items (rule: no panics in handlers).

- `.expect`/`.unwrap` in command paths: `chat.rs:25,200,226,238,270,280`, `download.rs:23,29,36`, `server.rs:114,162,219`, `cli.rs:297` (`download_installer`), `database.rs:355`. `lib.rs:85` is in a window-event handler. Replace with `Result`s or a poison-tolerant lock.
- Cancel registry leak: `chat.rs:208`. An error from the stream (`?`) returns before the entry is removed from `CANCEL_FLAGS`. Use a drop guard.
- Quadratic SSE buffer: `chat.rs:214–215` copies the whole buffer on every line. Use `drain`.
- `search_models` (`models.rs:259–308`) does not check the HTTP status before parsing, so an HF error page shows as "Failed to parse". Also `reqwest::Client::new()` is built per call in `download.rs:74`, `download.rs:290`, `models.rs:265`. Use the shared client in `AppState`.
- `run_geniex` (`models.rs:8–22`) has no timeout. A hung `geniex list` blocks the UI on every startup. Add a timeout, as `cli.rs` already does.
- Duplicated logic:
  - `check_for_cli_update` and `update_geniex` both fetch the GitHub release (`cli.rs:236–270`, `331–364`).
  - `fetch_loaded_models` and `fetch_loaded_models_from_response` do the same JSON parse (`server.rs:52–71`, `263–273`).
  - `probe_server` and `get_server_status` both hit `/v1/models`.
  - `DEFAULT_BASE_URL` duplicates `DEFAULT_PORT` (`constants.rs`).
- Magic numbers in `cli.rs` (5, 10, 300, 3, 100 seconds). Move them to `constants.rs`.
- Module boundaries: `import_gguf` (`download.rs:223–314`) registers a model in the DB and calls `geniex pull`. That belongs in a models module. `delete_directory` (`download.rs:204`) is a filesystem helper, so it belongs in a fs or download helper.
- Stale comments: `import_gguf` says it falls back to copy when `rename` fails (`download.rs:247`), but there is no fallback. `cli.rs:429` calls `UpdateInfo` a "re-export", but it is the definition.
- `load_sessions` (`database.rs:72–81`) matches messages with a nested `find`, which is O(n·m). Use a `HashMap`. It also loads every session and message at startup. Consider loading the list first and messages on demand.
- `list_downloaded_models` returns the full `model_card` text for every row, but the library grid only needs the name, precision and sizes.
- `init_database` (`database.rs:30–36`) runs `PRAGMA foreign_keys = ON` on one pooled connection only. sqlx enables foreign keys per connection by default, so the pragma is redundant. Remove it, or set it through the connect options.
- Migration `m20261020_000001` (`add_repo_columns.rs`) ignores every `ALTER TABLE` error with `let _`. Check `PRAGMA table_info` first, so real failures surface.
- `delete_session` runs two statements without a transaction (`database.rs:133–142`).
- Lint: default clippy is clean, but `.unwrap()` and `.expect()` are not flagged. Consider `clippy::unwrap_used` for command modules.

## 4. Security hardening (local app, but the webview is still untrusted input)

- `download_file` (`download.rs:47–65`) joins `file_name` onto the Downloads directory without checking it. `../` or an absolute path can write outside that folder. Accept only a bare file name (`Path::file_name() == Some(name)`).
- `delete_directory` (`download.rs:204–213`) removes any path the webview sends, recursively. Restrict it to paths under the Downloads directory, or delete by model id.
- `download_file` accepts any URL. Limit it to `https://huggingface.co/` and the expected GitHub asset host.
- `update_geniex` runs a downloaded `.exe` (`cli.rs:325`) without checking its digest. The GitHub release API returns a `digest` for each asset, so compare it before launch.
- `capabilities/default.json` grants `shell:allow-execute`, `allow-spawn` and `allow-kill` for `geniex`. The frontend only uses `shell.open` (`HubModelDetail.tsx:25`), and Rust does the process work. Remove the unused permissions.

## 5. Frontend structure and dead code

- **Two sources of truth for downloads**: `modelStore.downloads` (dead, see 1.4) and `downloadStore.downloads`. Delete the model-store copy and point the library and `Header` at `downloadStore`.
- **Two sources of truth for the port**: `serverPort` and `serverStatus.port` are set together in `setServerPort`. Derive one from the other.
- **Derived state synced by effects**: `Navigation.tsx:33–39` copies `isLocal` from location state into `useState` inside an effect. Read it directly. `modelStore.setServerStatus` also recomputes `activeModelId` inside the setter, which is acceptable but should be a selector.
- **Module-level mutable state**: `fileToRepoMap` (see 2.1), `resultCache` in `hubBrowseStore.ts`, and `releaseAssetsCache` in `hubApi.ts`. Move them into a store or remove them.
- **Dead code**:
  - `hubApi.ts` lines 174–350: the release-asset block (`fetchReleaseAssets`, `normalizeAsset`, `parseReleaseAssets`, `FALLBACK_CHIPSET_SLUGS`, `matchChipsetSlugs`, `assetCompatibility`, `singleDownloadOption`, `releaseAssetsCache`). Only the `ReleaseAsset` type is re-exported, from `types/index.ts:26`. Remove it, or wire it up if it was meant for the card UI.
  - `hubApi.ts:465` `parseParamCount` and `hubModels.ts:49` `parseGGUFPrecision`: no callers.
  - `geniex.ts:33` `pullModel` and Rust `pull_model`: no UI callers. The docs describe hub pulls as legacy.
  - `chatStore.ts` `renameSession`: no callers, and renames are not persisted.
  - `Navigation.tsx:27` `downloading`: see 1.4.
- **Duplicated code I should own**: `ggufGroups.ts` (`convertToGGUFFiles`) repeats the mapping in `hubModels.ts` `listGGUFFiles` (lines 21–43). I moved it out of `HubModelDetail` in the last change and kept the duplication. Have `listGGUFFiles` return the output of `convertToGGUFFiles` (after the `isGGUF` filter), so there is one path.
- **Service-layer rule**: `invoke()` lives only in `src/services/`, but three components make direct network calls: `AppSettings.tsx:146` (port probe), `AppSettings.tsx:74` (`listen`), and `AppBootstrap.tsx:288` (HF config fetch). Move them into services. Build `http://127.0.0.1:${port}` once in a helper; it is currently repeated in `ChatInput.tsx:66`, `AppSettings.tsx:146`, and the Rust constants.
- **Duplicate wrappers**: `download.ts` `cleanupDownloadedModelDirectory` and `deleteDirectory` do the same thing. `importGGUF` catches an error only to log and rethrow it.
- **Inconsistent imports**: `hubModels.ts`, `utils/gguf.ts`, `modelStore.ts` import with `.ts`/`.js` extensions. The rest of the codebase does not.
- **Logging**: `console.log` in `AppBootstrap.tsx:57` is noise in production.
- **Chat streaming cost**: `updateLastAssistantMessage` concatenates the whole message and recomputes `contextChars` on every chunk. Accumulate in a ref and commit at intervals.
- **Hub search fan-out**: `LocalModelsBrowserPage.tsx:176–184` fires one GGUF tree request for each of up to 20 search results, with no in-flight de-duplication and no concurrency limit. That is a rate-limit risk (HF returns 429). Cap concurrency, and cache in-flight promises.
- **Startup is sequential**: `AppBootstrap.tsx:37–83` waits for the CLI check, then the GitHub update check (up to 10 s), before loading sessions, models and server status. Run them in parallel with `Promise.allSettled`, and start the update check after the first render.

## 6. Tests and tooling

- No tests exist. Start with pure functions that are easy to cover and already have subtle behaviour: `parseGGUFFilename` and `groupGGUFFiles`, `filterToTag`, `strip_precision`, `version_less_than`, `find_arm64_installer`, the cancel and resume state machine, and `fetchDownloadedModelMeta` (which is where bug 7 would have been caught).
- `package.json` has `"allowScripts"`, which is not a standard npm field. Check whether it is needed.
- `README.md` is a stub.
