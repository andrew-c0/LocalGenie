# LocalGenie open tasks, easiest to hardest

Source: `tasks.md`. Done items are removed; what is done and what was dropped is listed at the end. Estimates are rough, from the wording and the current code. Ordered by complexity and time, easiest first, with dependencies noted. Nothing here has been started.

| # | Task | Estimate | Why |
|---|------|----------|-----|
| 1 | Installed models: sections by destination (chat, Playground tools) | Small | Mostly covered: the Local page has the family chips for chat models and a Playground chip that lists each tool's models with delete. What is left is to decide whether it needs explicit Chat and Playground sections (the original wording said horizontal sections) and to rename the "Audio to audio" group label, which still names the old tool now that the three audio tools are the one Audio tool. Mostly wording and a small layout change. |
| 2 | Downloads retry by themselves when the connection returns | Small to medium | A failed download (Hugging Face, AI Hub, runtime or Playground) stays failed until the user presses Retry in the drawer. When the failure was a network one (`classifyNetworkError` says offline, rate limited or timeout) and the browser comes back online (`useRetryWhenOnline`), the drawer would resume it on its own. The backend already resumes `.part` files. Needs a rule for how many automatic attempts, a way to tell a network failure from a bad file, and a notice that it is retrying. |
| 3 | Playground selector: "Find more on Hugging Face" (search with pre-filled filters) | Medium to large | The selector's last row is a disabled "Coming soon". OCR: reuse the existing Hugging Face search (OCR models are GenieX models) with an OCR filter pre-filled. Image tools: search limited to the supported families (Stable Diffusion, FLUX, Z-Image), with an "unsupported" message for any other repo. That needs a small Rust command that resolves a repo to a download recipe and a data table of supported families. Speech, upscaling and audio stay on their catalogs until more models are enabled. |
| 4 | Install, update and uninstall pipeline, including removing all models and runtimes on uninstall, and app updates | Large | The bundle targets are `all` and there is no updater plugin yet. Needs an installer decision (NSIS or MSI) with custom uninstall steps that also remove downloaded models and runtimes outside the install folder, with a clear confirmation because it deletes user data; an updater plugin, a signing key and a release feed for app updates; and then a notification for app updates (runtime update notifications already exist and can be reused). Touches release engineering as much as code. |
| 5 | Research adding native tools (web search, file explorer) with user consent | Large | Needs a consent and approval design before any tool runs, then tool execution, a permission model and a settings page that shows and toggles the tools. Open-ended; touches safety. |
| 6 | Research agentic mode, similar to OpenClaw or Atomic Agent | Largest | Broad; touches tools, planning and safety. Depends on the native tools research and the finished compaction, so it comes last. |

Smaller follow-ups to compaction, not started: a per-chat override and a "Compact now" button; stripping `<think>` blocks from the normal history; a database-level guard so `delete_message` refuses rows a summary covers (today only the UI, store and retry refuse); keeping error text out of the history sent to the model.

## Scrapped
- Run multiple models at once on the CLI (one per compute, each on its own server port). Scrapped on 2026-10-31 because the computes share memory bandwidth, so models running side by side would slow each other down; not worth it yet. It was built and tested (per-port servers, per-compute port settings, a multi-load selector with an active model) and then reverted. Kept from that work: the RAM estimate per downloaded model and the RAM headroom setting. Findings and risks: `memories/research/multi-model-plan.md`; the server test results: `memories/repo/geniex-server-behaviour.md`. Revisit if bandwidth turns out not to matter for the intended pairings.

## Dropped
- Video models (text-to-video, video-to-text): the Playground Video tab was removed. Too heavy for this hardware. Video-to-text with a vision-language model through GenieX was never looked into.
