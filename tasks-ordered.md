# LocalGenie open tasks, easiest to hardest

Source: `tasks.md`. Done items are removed; what is done and what was dropped is listed at the end. Estimates are rough, from the wording and the current code. Ordered by complexity and time, easiest first, with dependencies noted. Nothing here has been started.

| # | Task | Estimate | Why |
|---|------|----------|-----|
| 1 | Native notifications for runtime updates | Medium | The update checks already exist (`runtimeStore.updatesById`). Adds the Tauri notification plugin and its capability, a trigger when an update appears, a click that opens Settings > Runtimes and a setting to turn it off. App updates are a separate, later item (see the install and update pipeline). |
| 2 | Sort local downloaded models into horizontal sections by destination (chat, Playground tabs) | Medium to large | The Models page lists only GenieX models. Playground models (image, upscaling, speech, audio) live in their own catalogs and folders, outside GenieX, so the page must merge those catalogs and their delete and download actions. OCR models are the exception, being imported into GenieX. The Installed models page and the shared row component are the place for it. |
| 3 | Playground redesign: better organised tools and use of space | Large | Design-heavy across seven tools. No longer blocked: the Playground has its own landing page and one sub-page per tool, so the redesign is about each tool's layout (inputs, model picker, results, history), not navigation. |
| 4 | Install, update and uninstall pipeline, including removing all models and runtimes on uninstall, and app updates | Large | The bundle targets are `all` and there is no updater plugin yet. Needs an installer decision (NSIS or MSI) with custom uninstall steps that also remove downloaded models and runtimes outside the install folder, with a clear confirmation because it deletes user data; an updater plugin, a signing key and a release feed for app updates; and then the app-update notification from the notifications item. Touches release engineering as much as code. |
| 5 | Research adding native tools (web search, file explorer) with user consent | Large | Needs a consent and approval design before any tool runs, then tool execution, a permission model and a settings page that shows and toggles the tools. Open-ended; touches safety. |
| 6 | Research agentic mode, similar to OpenClaw or Atomic Agent | Largest | Broad; touches tools, planning and safety. Depends on the native tools research and the finished compaction, so it comes last. |

Smaller follow-ups to compaction, not started: a per-chat override and a "Compact now" button; stripping `<think>` blocks from the normal history; a database-level guard so `delete_message` refuses rows a summary covers (today only the UI, store and retry refuse); keeping error text out of the history sent to the model.

## Scrapped
- Run multiple models at once on the CLI (one per compute, each on its own server port). Scrapped on 2026-10-31 because the computes share memory bandwidth, so models running side by side would slow each other down; not worth it yet. It was built and tested (per-port servers, per-compute port settings, a multi-load selector with an active model) and then reverted. Kept from that work: the RAM estimate per downloaded model and the RAM headroom setting. Findings and risks: `memories/research/multi-model-plan.md`; the server test results: `memories/repo/geniex-server-behaviour.md`. Revisit if bandwidth turns out not to matter for the intended pairings.

## Dropped
- Video models (text-to-video, video-to-text): the Playground Video tab was removed. Too heavy for this hardware. Video-to-text with a vision-language model through GenieX was never looked into.
